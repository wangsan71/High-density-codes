## 决策（本轮新增，勿回退）

1. **`monoSafe` 三档**是容量/鲁棒性的唯一显式旋钮，写进 profiles 表与 CLI：
   - `full`：校验字节 ≥ 色道字节 → **整条色道不可读**（单色打印/缺料/换错色）仍可复原，代价是码率 1/2。
   - `partial`：校验 = 色道一半 → 抗 ~50% 色道单元丢失，不抗整道塌陷。
   - `off`：数据铺满所有通道 + 轻校验（223/255）→ 最密，无塌陷保护。
   实测（0.2 喷嘴 / 200mm 板）：`PL-D3(off)` 10481 B/页 > `PL-D3S(partial)` 8064 > `PL-D2(full)` 4032 > `PL-M1` 3345。
2. **双色确实比单色更省**：`PL-D2@0.4` 净 1342 B/页 > `PL-M1@0.4` 1115 B/页，且额外带整道塌陷保护（单色档的校验得从同一条道里抠）。
3. **帧摘要覆盖明文**（不是密文/压缩文）：口令错 → `digest-mismatch` 干净拒绝，绝不静默产出垃圾。
4. **RS 分块自动塞满单元格**（先定块数再定 k），`PL-G@0.4` 从 127 B/页 提到 216 B/页。
5. **摘要即会话 ID**：`sessionId = sha256(明文)[0..8]`，两批数据天然不可能串台（已测：异会话页 100% 被拒）。
6. `PL-D3` 从"单色可回退"改为 `monoSafe:'off'`（4 色 2bit 色道 + 1bit 形状道在数学上给不出 ≥ 数据的校验量）；想要 4 色 + 保护用 `PL-D3S`。

## 已知风险 / 待办

- `PL-G` 的"通用"指**单元格大到任何喷嘴都印得出来**，不是"一张版通吃所有喷嘴"：节距仍按目标喷嘴的 EW 整数倍量化。文档必须写清"不知道对方喷嘴就选 0.8"。
- 渲染层（M2）要用比值型字形判别（中心特征/参考环面积 ρ），否则 0.2↔0.8 的形状档位会串。
- **本机构架陷阱**：绝不能用 `Get-Content`+`Set-Content` 改写源码（CP1252 往返把注释里的 `— ≤ →` 打成 U+FFFD/C1），改文件一律用 edit 工具；已留 `tools/fix-mojibake.mjs` 做检测/修复，`npm run lint:eol` 待加。
