## 怎么读这份账

| 标记 | 含义 |
|---|---|
| ✅ **通过** | 判据全部满足，且证据命令能独立复现 |
| 🟡 **部分** | 判据的某一部分满足，**未满足的部分逐条列出**（不折算成百分比当成绩 ✓） |
| ⬜ **未开始** | 一行证据都没有 |
| ❌ **已知缺陷** | 有证据表明不满足，且原因已定界 |

贯穿全表的一条底线：**误接受是唯一不可原谅的失败**（帧 CRC16 + 页头 magic/version/CRC16 + 明文 SHA-256 摘要 + 原子写）。目前所有失败案例都是"拒绝且不写文件"，**没有一例静默误接受**。

## 逐条判决

`docs/PLAN.md` 是绑定契约；独立实现只需文本即可产出一致结果。

### 🟡 G2 · 纸面 300/600 dpi 扫描 100% 还原（判据：200 seed × ≤1 MB）
**已证**：200 KB 载荷 × 32 份平板语料（`scan300`/`scan600` × seed 1-16 ✓ `--modifier nocrop` = 平板扫描仪的物理正确模型）⇒ **30/32 = 93.8% 逐字节**、364 s ✓ 摘要由工具**进程内重算**（不是 grep CLI 的措辞 ✓）。比率在样本量翻倍时未变 ⇒ 不是小样本运气 ✓
**失败已分类**：`no-page-header` ×1、`short 0/1` ×1（都是 scan600 seed 3 那一类 ✓ 第 10 轮起未解、未回归 ✓）
**差的量**：32 → 200 seed ✓ **25 倍**
**差的原因（已定界，不是"再跑跑就好"）**：
- ❌ **600 dpi 阈值标定缺失**：物理 σ 固定时 dpi 翻倍 ⇒ 每像素峰值覆盖率约减半 ⇒ Otsu 只剩笔画核 ⇒ 60 px 角标量成 30 px ✓ 而 `otsu/peak` 四页都是 0.56–0.59 **完全不判别** ✓ 可用的信号是**实测着墨率 ÷ 期望着墨率**（失败页 3.34% 对健康页 6.5–9.7% ✓ 期望值可由页内自描述的 `cols×rows×字母表` 算出 ⇒ 尺度无关、不需 manifest、不需 dpi ✓）⇒ 待实现 `pskit calibrate`（M7）
- ❌ **阈值阶梯是调参不是标定**：现为双向 `[1,0.85,0.7,0.55,1.35,1.7]` ✓ 困难页最坏 6 次全图连通域 ≈ 4.9 s/页 ✓ 与 G6 记的 430 ms 差一个量级 ⇒ 正解是先由直方图统计判方向（一次 O(N) ✓）
复现：`python sim/channel.py --in .tmp/sw-scan300-src --out .tmp/nc-scan300-9 --seed 9 --preset scan300 --modifier nocrop` 然后 `node tools/g2-corpus.mjs --root .tmp --match "nc-scan*"`（不足 100% 即 exit 1 ✓）

### ✅ G5 · 误接受实测 0
复现：`node cli/pskit.mjs verify --gate G5 --trials 10000` → 9200 次被 ECC 纠正回原值、800 次拒绝、**0 误接受**；7 种损坏模式混合。
