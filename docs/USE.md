# 怎么用 · PSKT（打印—扫描传文件）

**这套东西现在就能用。** 本文件是给用户看的操作手册；判据与实测在 `docs/ACCEPTANCE.md`，门限状态与下一步在 `docs/STATUS.md`，已知问题在 `docs/DEFECTS.md`。

- 零运行时依赖：`package.json` 的 `dependencies` 恒为 `{}` ⇒ **不需要 `npm install`** ✓
- 全程气隙：不联网、页面里没有任何外部 URL，数据只走"打印出来的图案" ✓
- 需要 Node（本机 v24.14.0 ✓）。只有"模拟打印+扫描"那一步需要 Python 3.10 + numpy + opencv（真打印真扫描时不需要）。

## 0. 第一步：构建客户端页面（**刚 clone 必做**）

`web/dist/` 是**构建产物**，被 `.gitignore`（第 4 行 `web/dist/`）忽略 ⇒ **仓库里没有现成可打开的页面**（`git ls-files web/dist` 返回 0 个文件 ✓ 实测）。所以第一件事是构建：

```powershell
node tools/build-web.mjs        # 生成 web/dist：原子替换目录，含 SW 预缓存清单与 PWA 图标
node tools/check-dist.mjs       # 校验产物（含图标安装性：192/512/maskable 缺一个就红）
```

- 构建器**零依赖、离线可跑**；PWA 图标也是它用本项目自己的 `renderPageBitmap` + `encodePNG` 画的（不引图像库 ✓ 构建不可能声称一张它画不出的图）。
- **别背文件数与断言数**：它们随构建内容变。第 53 轮把浏览器自检改成跑"整张纸"的形状后实测 **`web/dist` 54 个文件**、`check-dist` **`13 pass / 0 skipped / 0 fail`** 且 **`G9 CHECK: all 12 assertions pass`**（第 56 轮复量仍是这两个数 ✓ exit 0）。判"构建好没好"**只看 exit code 和它自己打印的汇总**，别拿本文档里的数字对不上就当失败 ✗（§2 的 SW 预缓存条数同理，那个数字每加一个资源就变）。
- **改了 `core/` 就必须重建**：dist 里内联了 `core/`，不重建等于拿旧内核当新产物用 ✗（这也是仓库自己的规矩）。
- **`check-dist` 的最后一项断言自带夹具**（第 64 轮起，`docs/DEFECTS.md` D53）：它要"用出厂 bundle 去读盘上的页图、再核对摘要"，所以需要一批页图 + `manifest.json`；**缺失时它自己进程内生成**（确定性填充、整张纸形状、不用 `Math.random`）并在输出里明说 `[fixture generated in-process this run: a fresh clone has no .tmp]` ⇒ **全新 clone 也应当是 `G9 CHECK: all 12 assertions pass`、exit 0** ✓ 此前它默认读 `.tmp/g2src`（只有开发树里才有）⇒ 新用户照本节走会拿到 **exit 1**、误以为构建坏了 ✗ 想用自己的语料：`node tools/check-dist.mjs --pages <目录>`。
- 只想验证"构建出来的东西是不是自洽的"：`node tools/check-dist.mjs`；想验证"经 http 服务出去是不是自洽的"：见 §2 的 `tools/check-lan.mjs`。

## 1. 电脑端：双击就能用（`file://`，无需服务器）

| 要做什么 | 打开哪个文件 |
|---|---|
| **发送**：把文件变成可打印的页 | `web/dist/pskt-send-file.html`（单文件版，内核已内联） |
| **接收**：把扫描/照片还原成文件 | `web/dist/pskt-file.html`（单文件版） |

发送页：拖入或选择文件 → 选 profile（纸面 `P-M1-300`；实体码牌 `PL-D2`）→ **一次传输最多 255 页**（协议上限，`P-M1-300` 默认 20% 校验页下约 **1.5 MB** 的不可压数据；压得动的文件可以更大 —— 见下文「故障排查」）→ 下载 **页图 PNG（按钮写着「PNG（zip）」：所有页打在一个 zip 里、一次下载完（页面上的**预览只画前 8 页**，并会说明还有几页没画：每张预览是 base64 图片、浏览器还要把它解码成位图（A4/300dpi 每页约 35 MB），页数一多手机发送端会卡 ⇒ **产物里一页不缺**，要逐页看请下载 zip） ⇒ 不必跟浏览器的"批量下载拦截"打交道；里面每页一张 PNG，同样是整张纸：码区居中 + 裁切/套准标记 ⇒ 第 52 轮起，D45 已闭）** / **`pack.pdf`（页 = 纸张、码区按真实物理尺寸居中、含裁切与套准标记，直接送打印机）** / 板材 **`.3mf` + `.stl`**。
接收页：把**整盘**扫描或照片一次拖进去（可以乱序、可以缺页，页面会报缺哪几页；页间有 RS 冗余，少量缺页能自动补回）→ 还原后落盘。**存成什么名字可以自己填**（可选输入框，桌面接收与手机连拍两处都有）：页头**没有文件名字段**（只有摘要），所以留空就用从字节导出的默认名 `pskt-<字节数>B-<摘要前12位>.bin`；**手机上想直接打开，就填回原来的名字带扩展名**（例如 `report.pdf`；只填 `.pdf` 也行 ⇒ 把默认名的 `.bin` 换成它），因为 iOS/Android 靠扩展名决定用什么打开文件。填的名字**只在你本机用于命名下载**，不发送、不进页码、不参与校验（第 69 轮加，D62）。**若发送时加了口令**：在第 2 节「口令（若打印时加了口令）」里填上，再按「3 · 开始还原」；页收齐却缺口令时页面会明说「需要口令」而**不是**报缺页，填好后**再按一次**即可（已选的文件不用重选）。手机连拍那一节也有自己的口令框，但必须**在按「开始连拍」之前**填（见 §2；第 73 轮才有这一格，D66）。

> 为什么有"单文件版"：`send.html` / `index.html` 是走 ES module 的瘦版，**浏览器在 `file://` 下拒绝加载 module**（CORS），所以双击必须用单文件版。瘦版经 http 提供时同样可用（见 §2）。

**自检入口**（确认你这台机器的浏览器真能跑解码路径）：在接收页地址后加 `?selftest=1`，例如
`file:///D:/.../web/dist/pskt-file.html?selftest=1`

## 2. 手机端：一条命令起局域网服务

**手机接收该打印哪一种档？（第 247 轮更新 —— PL-G 那档已退役）**：**先看这条算术，它决定一切**：照片里**每格占多少像素 ≈（照片中纸宽的像素数 ÷ 210 mm）× 0.847 mm**。第 80 轮实测的 **2.7 px/格** 来自 G4 的 `phone-hard` 预设（**1280×960**、整张 A4 塞进去）；换成**手机满分辨率**（例如纸宽占 ~3000 px）⇒ **约 12 px/格**（**这是按上面公式算的估算，不是实测**），远超「5–6 px 就能读」的阈值。

**⚠ 退役之后没有任何档位被标成「手机拍摄首选」了**（第 247 轮：那个标记原本挂在 `PL-G` 上，而它已退役 ⇒ 标记指向一个网页端不再提供的档位，所以**标记被移除、机制保留**；**没有被挪到纸面档上** —— 那等于用估算推翻一次实测）。所以手机这一端现在**只有上面那条算术**可依据，而**真机验证正是你接下来要做的那件事**（G4 目前零证据）。

⇒ **你现在该这么做**：用默认的 **`P-M1-300`**（**退役之后在册最粗的纸面档**），手机**用满分辨率**、**整页连同四角标一起入画**、**关掉任何裁剪/滤镜**。**「拍近一点」不是出路**：四个角标在纸的四角，任何能用的照片都必须把整页装进画面 —— 再近角标就出画，页面**完全定位不了**（实测：裁到只剩码区 ⇒ 直接拒绝 `no-rectangular-quad`）。**「把纸打大一点」也不是出路**：格子占的像素只取决于**页上有多少格**，与纸多大无关（实测：按 200% 打印再过手机档，仍然 `no-contrast`）。

**关于 `PL-G`（历史，别在网页端找它）**：第 80 轮实测粗档板材 `PL-G@0.4` 在同样 1280×960 下格子还有约 **15 px**（**8/8 逐字节还原**，裁切生效时 6/8）—— 所以当时手册推荐它。但 **3D 板材线第 109 轮被产品负责人取消、第 110 轮记 RETIRED** ⇒ 所有 `PL-*` 档位标了 `retired: true`：**仍可解码，但网页发送端的下拉框里不再出现**（CLI 显式 `--profile PL-G --nozzle 0.4 --plate 200` 仍然可用）。手上有旧板材页的话照旧能收。
手机要用**摄像头连拍接收**（`web/dist/index.html`，带 PWA `manifest.webmanifest` + `sw.js`），而摄像头、module、service worker 在 `file://` 下都不可用 ⇒ 必须经**服务器**打开：**但注意「经服务器」不等于「经 http」**（第 248 轮更正）—— **摄像头只在安全上下文里可用**（`https://` 或 `localhost`），所以 `http://192.168.1.x:8123` 这个局域网地址**能上传文件、不能开摄像头**（页面会自己禁用那个按钮并说明）。要摄像头就用下面 §5 G4 那三条路（已部署的 https 接收页 / 系统相机 + 选择文件 / Android 白名单）：

```powershell
# 在电脑上（仓库根目录）—— 只需要 Node，不需要 Python
node tools/serve.mjs
```

它会**自己打印该打开哪个地址**（本机 + 每块网卡的局域网地址），实测输出：

```
serving D:\Desktop\Apps\3D_print_scan_to_send_file_or_things\web\dist
  this machine : http://127.0.0.1:8000/index.html
  phone on the same LAN, open one of:
    http://192.168.100.104:8000/index.html   (乙太網路)
```

手机连**同一个 Wi-Fi**，打开上面那行局域网地址即可；自检在同一地址后面加 `?selftest=1`。`Ctrl+C` 停止。

- **端口被占时它自己往上走**（8000 → 8001 …）并说明原因；但**你显式给了 `--port` 就绝不偷偷改**（只报错 + 告诉你怎么查）⇒ 实测两条路径都对 ✓
- Windows 上"端口被占"有**两种**成因，只有一种能在 `netstat -ano | findstr LISTENING` 里看见：另一种是**某个出站连接临时把它当自己的本地端口**（本机实测：8131 被一条到 `142.250.157.188:443` 的 ESTABLISHED 连接占着，`LISTENING` 过滤和 `Get-NetTCPConnection -LocalPort 8131` **都查不到**，而 `bind` 就是报 `EADDRINUSE` ✗）⇒ 排查时用 `netstat -ano | findstr :端口`（**看所有状态**，别只看 LISTENING）
- 也可以用 Python（等价，但需要装 Python）：`python -m http.server 8000 --directory web/dist`，再 `ipconfig` 自己找 IP ⇒ `tools/check-lan.mjs` 对这两种服务器都给出一样的结论（实测 52/52 字节一致 ✓）

**如实说明（别期待错）**：PWA 的"添加到主屏幕/离线安装"要求 **https 或 localhost**，局域网 http 源会被浏览器拒绝 ⇒ 代码里也照实处理了（`pskt-file.html` 只在 `secure` 时才注册 `sw.js`）⇒ **手机上能用，但装不成离线 PWA**。要真装需要 https 托管：`.github/workflows/pages.yml` 还没写（见 `docs/STATUS.md`），而且 GitHub 推送本身还等你的仓库地址与凭据。**D43 当初有两个各自独立的安装阻塞，图标那一半第 44 轮已经修好**：manifest 现在声明 `icon-192.png` / `icon-512.png`（`purpose: any`）+ `icon-maskable-512.png`（`purpose: maskable`，画在 **80% 安全区**内，因为自适应启动器会从中间裁圆/裁方角，裁掉的正好是基准块——这张图里唯一有意义的部分 ✓），而且 `tools/check-dist.mjs` 把它变成**构建期强制**（缺 192/512 或 maskable 就红 ⇒ 不会烂回去 ✓）⇒ **只剩 https 那一半，而且只有你能解**（仓库 URL + 交互凭据 + `pages.yml`）⇒ 记在 `docs/DEFECTS.md` **D43**。

**不用手机也能先验一遍"服务端这半是真的"**（第 50 轮两条都实测 exit 0）：

```powershell
node tools/serve.mjs --port 8137          # 一个终端（后台起也行：Start-Process node -ArgumentList 'tools/serve.mjs','--port','8137' -WindowStyle Hidden -PassThru）
node tools/check-serve.mjs --port 8137    # 验这台服务器本身的行为
node tools/check-lan.mjs   --port 8137    # 验它交出去的资源与构建清单逐字节一致
```

`check-serve`（10 项）验的是**服务器行为**：`/index.html` 与盘上文件 **sha256 相同**、`GET /` 与 `/index.html` 是同一份文档、**四种目录穿越全部被拒**（`/../package.json`、`/..%2fpackage.json`、`/sub/../../package.json`、`/%2e%2e/package.json` ⇒ 实测 403/404、**没有一个字节泄漏**；这台服务**默认绑所有网卡**，而一个会回答 `../` 的静态服务等于整盘可读 ✗）、缺文件是 **404 而不是回退首页**（打错字不能看起来像成功 ✗）、`HEAD` 正常、`manifest.webmanifest` 的 **MIME 正确**（类型错了浏览器就不当 manifest 解析）、响应带 `no-store`（重建后下一次请求即生效，不必等缓存过期）。
`check-lan` 验的是**交出去的内容**：把 SW 预缓存清单里**每一条**资源 fetch 下来、用我们自己的 `core/hash.js` 比对 sha256（**52/52 一致**；这个数字等于本次构建预缓存的资源条数、会随构建变化——第 44 轮加图标后从 48 变 51、第 52 轮改 `core/` 重建后变 **52** ⇒ 看它是否等于构建打印的 `precache entries` 即可，**不要当常数背** ✗）；扫 4 个页面有没有**外部 URL**（`src=`/`href=`/`fetch()`/`import()`，只豁免 `xmlns` 命名空间串 ⇒ 气隙契约在 http 源上同样成立 ✓）；确认瘦页模块图能解析、manifest 的 `start_url` 可取；并**报告** CSP meta 是否存在（实测 4 页都有 ✓）。两者都**不能**证明 SW 注册、安装提示、摄像头权限——那要真浏览器（G9 / D18）；`check-lan` 会把**剩下的那一个**安装阻塞（https）打印出来但**不计入通过与否**（报出来 ≠ 通过 ✓）。

发送端在手机上也能开（`.../pskt-send-file.html`），但小屏拖拽体验差 ⇒ 建议**电脑发送、手机接收**。

**连拍那一节（页面最下面「手机连拍（自动挑帧）」）的两个输入框，第 73 轮起才齐**：

- **口令（若打印时加了口令）**：发送时用了口令（发送页的「口令（可选，加密载荷）」，或 CLI 的 `--passphrase`）就**必须在按「开始连拍」之前填** —— 连拍不会把已解出的页留着（在手机上常驻每页的判读结果太贵），所以**事后补口令要重拍**。缺口令时页面不会假装成缺页：它明说「页收齐了，但这批是加密传输」，并且**一个字节都不写**；口令**错**了也一样被摘要门挡住（`digest-mismatch`），不会给你一个打得开但内容错的文件（判据③：误接受 0）。这一格第 73 轮才加上 —— 之前手机连拍**根本没有口令框**，加密传输在手机上造得出、收不了（D66 已修）。
- **存成什么名字（可选）**：见 §1（手机上要带扩展名才打得开，D62）。
- 进度行随时报「已收 N/M 页 · 缺 3,7」⇒ **缺哪几页是点名的**：**在同一次连拍里**继续对着那几页拍就行（收满自动停、自动组装）；但一旦按「停止」或刷新页面，装配状态就没了（`asm` 与收集器都是在按下「开始连拍」时新建的），得重拍整批。

## 3. 真打印 / 真扫描 / 真拍照

- **打印**：用 `pack.pdf`（**页数不限**）。发送页那个「浏览器打印」按钮**只服务 ≤8 页**：它把每页位图写进一个新窗口，A4/300dpi 每页解码后约 35 MB ⇒ 168 页 ≈ **5.8 GB**，浏览器会卡死或打不开 ⇒ 超过 8 页它**直接拒绝并说明理由**（第 68 轮改的；原先是写完窗口才提醒 = 钱花完才说话），请改用 pack.pdf。**页就是纸**（`P-M1-300` ⇒ A4 210×297 mm），码区按**标称物理尺寸居中**放置（A4 上码区 191.35×278.55 mm ⇒ 距纸边约 9.3 mm），页边距里有**四角裁切标记**与**四边套准十字**（矢量绘制 ⇒ 任何打印分辨率都锐利 ✓ 修剪时沿裁切标记走即可）。打印对话框里**建议**选 **100% / 实际大小**、**关掉**"适应页面"——但这条比手册原来写的宽松：**实测（第 85 轮）被均匀甚至非均匀地缩放过的页照样能解码**（95%、110%、95%×100% 三种缩放全部逐格零错、逐字节还原），因为几何是从**四个角标**反算出来的，仿射缩放会被精确抵消 ⇒ 真正致命的是**裁掉角标**（16mm 切边实验 ⇒ 正确拒绝）和纸张卷曲这类非仿射形变。所以：被缩放别慌，先试着扫；但如果打印机的"不可打印边距"把角标切掉了，就选缩小到可打印区域（`适应页面`）反而更稳。（D8 的原始问题——印出来的实际尺寸是否等于 PDF 标称——仍要你用尺子量，见 §5）；产物侧则由 `tests/unit/pdf-truesize.test.mjs` 机器把关，D44 已闭 ✓）。**页图 PNG 现在也是整张纸**（第 52 轮起，D45 已闭）：之前只有 `pack.pdf` 是纸、PNG 是裸码区 ⇒ 打印 PNG 就没有留边也没有标记、码区摆在纸上哪里由打印机决定 ✗ 现在两者取自**同一份几何**（`core/render/sheet.js`，mm 单位、PDF 与栅格都调它 ⇒ 不可能各自漂移）：A4@300dpi 的 PNG 实测 **2480×3508**、600dpi 侧 **4961×7016**（210 mm@600dpi = 4960.63 px ⇒ 栅格必须取整像素、偏差 0.01%；PDF 侧仍是精确 mm），标记用机器墨画在留边里、笔宽 ≥2 px（1 px@300dpi = 0.08 mm 会被扫描仪 MTF 抹掉 ✗）⇒ 打 PNG 与打 PDF 是同一张纸 ✓ `tests/unit/raster-sheet.test.mjs` 逐像素盯着"标记不许碰码区"、并有阳性对照 ✓
- **扫描的格式**：**存成 PNG**。**黑白（1-bit）/ 灰度 / 彩色 / 调色板 / 16-bit 灰度都直接支持**（第 95 轮 D80 起：扫描仪的"黑白·线稿"默认档就是 1-bit 或调色板 PNG，以前会被拒 ⇒ 现在四种都实测逐字节还原，其中 1-bit 反而是最干净的输入）。**PNG 与 TIFF 两个容器都直接解码**（第 96 轮 D82 起：TIFF 是扫描仪另一个常见默认输出，且**多页 TIFF 会自动展开成多页**；容器支持未压缩/LZW/Adobe Deflate/PackBits、灰度/二值/调色板/RGB/16-bit，其它变体**具名拒绝**而不是猜）；JPEG/PDF 仍会明确告诉你「这个格式读不了」并给出转换命令；手机拍照那条路走浏览器接收端时不受此限（浏览器自己解 JPEG）。**特别提醒"扫描成 PDF"**：那是最多扫描仪的默认输出，而本工具**写得出一份 PDF（打印路径）却读不了一份** —— 目录里只有 `.pdf` 时它现在会直说这一点并让你导出 PNG（第 93 轮 D79），**不要靠截屏**：截屏会重采样墨点、把角标挪位置。
- **JPEG 拍照走 CLI 的转换工具（Windows）**：`& .\tools\jpeg-to-png.ps1 -Source D:\照片目录 -Out D:\照片目录-png`；它使用 Windows 自带 System.Drawing，不引入新依赖，随后对 PNG 目录执行 `receive`。
- **忘了打印时用的是哪个档？加 `--profile auto`（第 239 轮起）**：`node cli/pskit.mjs receive 目录 --photo --profile auto --out 回来的文件`。它跑的是**浏览器接收页那一套候选几何搜索**（`core/decode/bootstrap.js`）：**从页自己的页头读出几何**，并与产生它的候选**交叉核对**（页头说的档必须与候选一致，否则不算数）⇒ 是**核对**不是猜。实测：一个**没有 `manifest.json`** 的 3 页目录，10 个候选后认出 `P-M1-300@300`、逐字节还原 ✓。**代价是真的**：每页要试多个候选（数秒级），所以它是**你主动要**才跑，不是默认 —— 不带 `--profile` 时 CLI 仍然**具名拒绝**并告诉你这条路。
- **扫描**：**用 300 dpi**（这一档实测达标：200 seed × 3 页 ⇒ **200/200 逐字节还原**、门限 G2 的 300 dpi 侧 `exit 0` ✓）、**彩色**、**关掉自动裁剪/去边界**（会切掉角上的基准标记 ✗）。**600 dpi 不是必要路径**（第 63 轮用户明示：没必要 600 dpi、只要能读到就行 ⇒ 不再为它花门限时间；下列数字是历史实测，保留）：同一判据、同一载荷、同一信道口径（`nocrop`）下实测 **162/200 = 81%**，而且**页级直接读出只有 43%**（162 份"成功"里有 145 份是靠页间冗余把读不出的页兜回来的）⇒ 记 **D49 OPEN** ⇒ 在**电平判读改成"按页实测再定阈"**之前（**D51**：第 61 轮量到的根因是坏页**整页被判读成同一个电平**、**不是**"页内 ECC 余量不足" ⇒ 加冗余救不了它）——**这个前提第 63 轮已不成立**：电平判读现在就是**按页实测再定阈**（D51 修法落地：被页内码拒绝的页会按本页实测 ρ 切点重读一次，且只有页内 RS + 帧 CRC + 摘要都过才接受；桌面接收、手机连拍、G2 门限三条路共用同一段仲裁逻辑）⇒ 塌陷那一类失败已消除（600 dpi 重跑到 52/200 的中间普查里，旧跑 210 次的 `assemble/intra-fail` 出现 **0 次**），但**最终判决没取**（用户判定 600 dpi 非必要 ⇒ 重跑被中止；这不等于跑绿了 ✗）⇒ 照本手册走仍用 **300 dpi**（那一档在修法之后重跑仍是 `PASS 200/200`、`exit 0`）✓ 想自己量手上的扫描/照片：`node cli/pskit.mjs calibrate <页图片所在目录>` ⇒ 逐页打印 readout 结果与**页内纠错预算占用**（`0%` = 干净、`100%` = 整页崩、失败块明写 LOWER BOUND），**只量不改**：它不是门限（exit code 不是判决）、不派生阈值、不改任何解码判决 ✓ 相应地：CLI 里 `--profile P-M1-600` 仍然可选（**网页发送端的下拉框同样会列出它** ⇒ 我第 58 轮写的"网页不提供这一档"是**错判、第 60 轮已撤回** ✗ 那个下拉框是 `Object.entries(PROFILES)` 动态建的、档位 id 从来不以字面量出现，所以"grep 不到"证明不了"不提供"。第 60 轮起该选项的标签带 **`⚠ 实测未达标 (D49)`**，但**它仍然可选** ⇒ 别选），但**照本手册走就不要选它**；600 dpi 的失败形态是"缺页/读不出并点名要补拍"，**不会**交出错误字节（误接受 0 是硬约束 ✓）。
- **图片默认走密档（第 118 轮起）**：`send 一张图.png` 不带 `--profile` 时默认 **`P-MX-300-5`**（0.4233 mm 模块、**29,082 B/页**；旧默认 `P-M1-300` 只有 7,514 B/页）⇒ 同一张图**页数约少 4 倍**。依据是第 117 轮量出的规律：**拐点取决于"扫描 dpi 下每个模块几像素"** —— 4 px/模块在 300 dpi 上退化到 ~1.3e-3，5–6 px 归零，所以 300 dpi 平板扫描取 5 px 这一档。非图片文件仍走 `P-M1-300`（更保守）。
- **照片有两条路（第 134 轮起）：缩小到装得下（无损）／保留原尺寸、降质量（有损）**。两条都按你给的页数预算来，有损那条用自研编码器（零依赖），最多能保住原分辨率：

  ```powershell
  node cli/pskit.mjs send photo.png --image-mode lossy --pages 5 --profile P-MX-300-5 --format png,pdf --out DIR
  node cli/pskit.mjs receive DIR --photo --profile P-MX-300-5 --out photo-back.psk
  ```

  **一条命令就够（第 138 轮起）**：`--image-mode lossy --pages N` 会自己按预算选质量并打包，收回来的是 `.psk` 图片载荷（不是原 PNG）。想先把载荷存下来、看清它多大再决定打几页，就用两步：`node tools/fit-image.mjs photo.png --pages N --profile P-MX-300-5 --lossy --out photo.psk` 再 `send photo.psk`。

  ```powershell
  node tools/unpsk.mjs photo-back.psk photo-back.png     # 把收回来的 .psk 变回可看的 PNG
  ```

  **手机端（第 146 轮起）**：接收页收到图片载荷时会**直接把它还原成 PNG** 交给你下载/打开（不再是那坨 `.psk` 字节）；这条目前只有构建与 Node 侧等价路径证明过，**真手机第一次跑请留意**：若下载得到的仍是一坨字节，说明这一档没生效，请把日志行发我。

  **收回来的是图片载荷，不是原 PNG**：`receive` 交回的是发送端打包的那份 `.psk` 字节（逐字节相同、清单摘要可核）；用 `tools/unpsk.mjs` 解开就能看/存/转发，它用的是与发送端**同一份解码器**，不会二次损失。
  实测（1240×1754 的**带噪**合成照片、A4/`P-MX-300-5`，第 138 轮用**一条命令**复跑、载荷与两步走逐字节相同）：`--pages 5` ⇒ 选 **q10**、载荷 **72,358 B**、**PSNR 28.67 dB**、**不降采样**；`send` 实际写出 **4 页**（2 数据 + 2 校验 —— 比按载荷大小估的少一页，因为载荷本身还能被再压一层）。**页数一律以 `send` 打印的为准**，别自己按字节数除。

  会看到拒绝的时候：`--pages 3` 时这张图**放不下**，工具会明说 `even q5 needs 33537 bytes and the budget is 29082` 并给出路（加页 / 换更密的档 / 接受更小的图）。**判据 G-IMG 要求 PSNR ≥ 30 dB**，这条路上没达到时工具会自己打印 `NOT met` —— 想要 30 dB 就得加页或换档。

- **瓦片页（P4，像 QR 一样"认住任意一块即可"的新路子，第 160–167 轮）**：整页切成 M×N 块瓦片，每块自带三实心 + 一空心定位图形，载荷**分片**铺进去（每块带 2 字节头 + 2 字节长度）。一条命令写页、一条命令读回：

  ```powershell
  node tools/make-tile-page.mjs "要传的短文本" --out page.png
  node tools/make-tile-page.mjs --file payload.bin --out page.png
  node tools/make-tile-page.mjs --read page.png --out payload.bin      # 从页 PNG 读回载荷
node tools/make-tile-page.mjs --read photo.png --photo --sheet A5 --out payload.bin   # 从【照片】读回载荷
  ```

  **实测容量**：A4 / 30 mm 瓦片 / 33 模块 ⇒ 48 块（6×8），**4,800 B/页**（每块 100 B 有效）。**比 `P-MX-300-5` 的 29,082 B/页少约 6 倍** —— 差价买的是"每块自带定位图形"。超出容量会**具名拒绝**（不会悄悄截断）。

  **目前能做什么、不能做什么（别高估）**：能写页、能从**自己渲染出来的 PNG** 逐字节读回、能容忍**平移**（±12 px 内搜到、分辨率约一个模块）；**第 240 轮起能从照片读 —— 这是本格式存在的理由（不需要角标、不需要回显条、不需要 `manifest.json`）**。一条命令：

  ```powershell
  node tools/make-tile-page.mjs --read photo.png --photo --sheet A5 --out payload.bin
  ```

  它先**量出照片里纸的尺度**（打印区的墨迹包围盒 ÷ 模型里的纸面 mm），再据此找四角、把整页映射过去，最后**用瓦片自己**把映射重新拟合；每张成功时打印「认成多少 dpi、试了几个尺度、拟合到几个锚点、块号投票几票」。**实测**（第 240 轮，A5 4×6 瓦片、纸占画面宽 62%、转 2.5° 并带梯形）：**24/24 瓦片、0 孔洞、载荷逐字节一致**；模块 **5.45 px** 与 **9.09 px** 两档都过。

  **做法上的三条硬事实**（都是量出来的，别当成调参余地）：① 定位器对尺度**只容忍几个百分点** —— 同一张照片，尺度对 24/24 全过，偏 5% 就整页拒读 ⇒ 所以是「先量尺度，再在 ±3/6/9% 上试」，不是盲扫；② 量尺度靠**墨迹包围盒** ⇒ **纸必须比背景亮**（深色桌面会让这个测量失去意义，届时的拒绝语会直说这一点）；③ **合成夹具必须按照片自己的尺度渲染**：先按 300 dpi 渲染再压缩到 6 px/mm，会得到一个**非刚性**的模块栅格，读不出是**夹具的锅**，不是读取器的锅（第 240 轮第一版夹具就踩了这个）。

  **还没做**：整页 90° 旋转、光照不均；瓦片级 RS 纠错（现在只有 CRC 检测 + 每块 16 B RS 校验）；瓦片路径**没有接进 `pskit send/receive`**（它仍然是 `tools/make-tile-page.mjs` 这个工具级别的入口）。

  另一条（无损、缩小）：`node tools/fit-image.mjs photo.png --pages N --profile P-MX-300-5 --out fitted.png` —— 它降到 1/4 线性分辨率就不再降（判据下限），装不下会具名拒绝。

- **新的高密度纸面档 `P-MX-300-4/5/6`**：纸面模块改为**实心方块/空白**，不再画参考环；timing 行与较大的回显模块负责定位和黑白校准。模拟扫描固定 16 seed 下三档都是 16/16 逐字节还原，100 KB 多页传输与 **1 MB 不可压传输也全部逐字节还原**；它们**仍标为「新档·真机待验」**，不会冒充真扫描证据。不可压 1MB 的页数从默认 `P-M1-300` 的约 169 页降到约 **64 / 45 / 29 页**。用法：

- **拍照**：正对、四角完整、避免反光；接收走 `--photo` 路径（自动找标记 → 透视校正 → 读）。
- **想知道"我这条打印+拍摄链子能读到多细"（MTF 校准板，第 75 轮起）**：这块板把"该用哪一档喷嘴/节距"从猜变成量。板上有：五档**阶梯格**（0.6/0.9/1.2/1.8/2.4 mm，每档是一块实心块挖方格孔）、一列**孤立孔**（0.26/0.3/0.45/0.6/0.7/0.9/0.95/1.2 mm —— 四个喷嘴的挤出宽度**本身就是档位**）、每种料一块色样、实心/竖肋/横肋三块纹理样、150 mm 标尺、四角标记。

  ```powershell

  # 把 mtf-plate.png 按 100% 打出来（或以后用板材件打），然后用扫描仪/相机拍回来：

  ```

  它会逐档打印"孔中心覆盖率 / 孔周围墨量"，给出**能读到的最小特征**、**能用的最小节距**、颜色分离度、白平衡漂移、标尺刻度数，最后给一条建议（**喷嘴看孤立孔那一列、节距看阶梯格** —— 两者允许不一致，>1.5 倍时它会说明为什么）。**它不是门限**：exit code 不是判决，量不出就如实说量不出。

  **四个喷嘴一次量完（第 92 轮起 · `tools/mtf-matrix.mjs`）**：同一块板**用每个喷嘴各打一次**（喷嘴是切片软件/打印机的设置、不是文件 ⇒ 四块板应当长得一样），四张照片放进同一个目录、按喷嘴命名 `n02.png` / `n04.png` / `n06.png` / `n08.png`（名字认不出来就 `--label 0.4=n04.png`，或写一个 `mtf-labels.json`），再把 `mtf-plate.json` 一起拷进那个目录：

  ```powershell
  node tools/mtf-matrix.mjs --dir mtf-photos --provenance real-print
  ```

  逐张给出建议喷嘴与判决：`names-itself`（认出了打印它的那个喷嘴）、`allowed-coarser`（只有 0.2 那一档允许，且必须由读数说明"0.26 mm 孔被渗墨填了"）、`mismatch`（认成别的喷嘴）、`unregistered`（四角标记没找到）。**exit 0 = 每张都认对、1 = 有认错的、2 = 工具没跑起来**；**它不是门限** —— G10 要真打印机才算数，所以 `--provenance` 只是把你说的记下来（像素分不出真假，台账不会拿仿真件充真机件 ✓）。先想看它能不能跑：`node tools/mtf-matrix.mjs --selftest`（把板按四个喷嘴的挤出宽度各渲一次、读回必须点名自己，另加两条对照）。

  **两个已实测的结论，照手册走之前先知道**：① **0.2 喷嘴的板材用 300 dpi 扫描读不回来** —— 0.26 mm 的孔会被墨的渗展（信道模型里 0.05–0.15 mm）填死，300 与 600 dpi 都一样；② **整张 200 mm 板放进一张手机照片里（约 100 dpi）连 0.95 mm 的孔都读不出**，这时它会**拒绝推荐任何喷嘴** —— 这是实话，不是工具在挑剔。**别用"拍近一点"来救**（第 87 轮 D76 的教训在这里同样成立：角标在板四角，拍近就出画 ⇒ 连登记都做不到）：正确动作是**改用 300 dpi 扫描**，或如实接受"这一档读不出"。
  **可打印的实物（第 76 轮起）**：加 `--format 3mf,stl` 就会写出 `mtf-plate.3mf` / `mtf-plate.stl`（底板 2 mm + 0.3 mm 浮雕、每墨一个部件、**四角标记也建了模**）——`node cli/pskit.mjs calibrate --make-mtf --out mtf --format 3mf,stl` ⇒ 实测 561180 三角形、每个部件水密、投影与规格逐区对拍 **最差 0%**、3MF 过 G8 子集校验。丢给切片软件按你手上的喷嘴打出来、拍照，再按上面的命令读回来即可。**第 77 轮起**：**数据板（`pskit send --format 3mf`）的网格也带四角标记了**（D68 已闭）—— 三个实心 + 一个空心，尺寸取自版面布局（环宽 ≥ 一格挤出宽度，薄了直接拒绝出图）⇒ 打印出来的码牌照片**才有可能被 `receive --photo` 登记**。**仍未验**：真照片能不能锁住浮雕角标（单色板靠阴影、双色板靠料色），这只有真机能回答。

- **3D 码牌**：`.3mf` 直接丢给切片软件（Bambu Studio / Orca / PrusaSlicer 等）；`--nozzle 0.2|0.4|0.6|0.8` 决定最小可打印特征。实测 `PL-D2@0.4`：3 objects / 377964 triangles / 4.1 MB，且通过 3MF Core 1.4 子集校验（`verify --gate G8`）。

**一次能传多大**（实测数字与 CLI 自己的容量拒绝推算，不是估的）：

- 一次传输最多 **255 页**（页间 RS 的限制）⇒ 最大 payload ≈ 每页净字节 × **能留给数据页的页数**（不是 255：校验页要占位置。`P-M1-300` 默认 20% 校验页 ⇒ **212 个数据页 × 7514 B = 1,592,968 B ≈ 1.52 MB**；把校验页调到 0% ⇒ 253 × 7514 = 1,901,042 B ≈ 1.81 MB。实测：1 MiB → 168 页 ✓ 装得下（约 180 ms 编完），2 MiB → **48 ms 被拒**）。
- 纸面 `P-M1-300`：每页净 **7514 B** ⇒ 上限约 **1.9 MB**；200 KiB 的文件 = **3 页**（实测 ✓）。
- 新纸面模块档：`P-MX-300-6` 每页净 **20111 B**；`P-MX-300-5` 每页净 **29082 B**；`P-MX-300-4` 每页净 **44400 B**（均为 300 dpi，模拟 16/16，真机待验）。
- 板材 `PL-D2@0.4`：每页净**约 180 B** ⇒ 上限约 **46 KB**。拿 200 KiB 去喂它，CLI 会**直接拒绝**并给可操作建议：`needs 1120 pages > 255 (inter-page RS limit): shrink payload or use a denser profile` ✓ 这是设计行为（宁可拒绝，也不产出"看起来成功但是错"的东西）。
- **文件比上限大怎么办（第 72 轮起有工具，不再只是一句建议）**：装不下是**协议**给的（页头 `totalPages` 只有一个字节），CLI 走同一个 `encodeTransfer` ⇒ 也绕不过。唯一的出路是**切成几份、每份各传一次**，再把收到的几份**拼回去并校验**：

  ```powershell
  # 1) 切：默认每份 ≤1,400,000 B（在 1,592,968 B 上限下留 ~12% 余量），写出 part-NNN.bin 与 parts.json
  node cli/pskit.mjs split BIGFILE --out PARTS        # 想自己定每份大小就加 --max-bytes N
  # 2) 每一份都是一次独立传输：send → 打印 → 扫描/拍照 → receive 回**同一个目录、用同一个 part 名字**
  node cli/pskit.mjs send PARTS\part-000.bin --profile P-M1-300 --format png,pdf --out P0
  node cli/pskit.mjs receive P0-scan --photo --out PARTS\part-000.bin
  #    …… part-001.bin、part-002.bin 各来一遍（N 份 = N 轮打印/扫描，每份各有自己的摘要闸）
  # 3) 拼回去：逐份校验摘要，再校验整文件摘要，全过才写盘
  node cli/pskit.mjs join PARTS --out RECOVERED
  ```

  完整性口径与接收端一致（**误接受是唯一不可原谅的失败**）：缺一片、短一截、错一位 ⇒ `join` **拒绝、exit 1、一个字节都不写**，并说清"验到第几片/共几片"；不给 `--out` 时默认用 `parts.json` 里记的原文件名，但**那个文件已存在就拒绝**（不猜着覆盖）。文件名只是默认输出名，**不进纸面**（传输里只有字节与摘要，见 D62）⇒ **用网页或手机接收时也不用改名**：接收页**两个区都有「存成什么名字（可选）」输入框**（文件区 `#outname`、连拍区 `#burstname`，见 §1），直接填 `part-000.bin` 就按这个名字存；走 CLI 就用 `receive --out PARTS\part-NNN.bin`。（**更正**：第 72 轮我在这里写过"收完要把每份改名回 part 名"，第 73 轮核对 `web/index.html` L59/L91 与 `web/app.js` L127-133 后发现输入框早就有、并已接到 `downloadName({userText})` ⇒ 那句让用户多做一步的话是我没查源码就下的结论 ✗）这条链路由 `tools/usability.ps1` 的 **4b 腿**每轮实跑（split → 3 次独立传输过真实信道 → join → 逐字节比对，外加"收到的某一片改一个字节必须被拒"的阴性对照），纯函数侧由 `tests/unit/splitjoin.test.mjs`（6 个用例，每个拒绝都配阳性对照）盯着。
- 完整容量表（各 profile × 喷嘴）：`node cli/pskit.mjs status`

**命令行等价**（可脚本化，与页面走同一份 `core/`）：


## 6. 出问题时

- **用手机拍纸面页，一页都读不出**：先算这条 —— **每格像素 ≈（照片中纸宽的像素 ÷ 210 mm）× 0.847 mm**，**低于 ~5 px 就别指望了**。实测（第 79–80 轮，`tools/g4-probe.ps1`）在 **1280×960** 的苛刻预设下，整张 A4 塞进画面只剩约 **2.7 px**（符号错 72.83%、0/8）；**满分辨率手机照片**（纸宽 ~3000 px）按同一公式是 **约 12 px/格** ⇒ 那种情况下失败**多半不是密度问题**，而是前面那几条：纸没全部入画、被裁剪/滤镜动过、反光或失焦。**`PL-G@0.4` 那条粗档捷径已随 3D 板材线退役**（第 110 轮 RETIRED：网页端不再提供，CLI 显式指定仍可用）；旧记录保留在此作历史：粗档板材 `PL-G@0.4` 的格子~~还有约 15 px ⇒ 同一套取景下纸面 0/8、板材 8/8 逐字节还原~~。**退役之后的两条出路**：① 手机**满分辨率 + 整页（含四角）入画**（`P-M1-300` 就行，见 §2 那条算术）；② 改用**扫描仪 300 dpi**（这一档实测 **200/200 逐字节还原** ✓）。**「拍近」不是第三条**：角标在纸的四角，拍近就会把它挤出画面 ⇒ 页面完全定位不了（实测：裁到只剩码区的页被直接拒绝）。工具现在会区分原因：说 `no-contrast` 就是曝光/反光/太远，说 `echo-no-contrast` 就是「条带（页上最细的特征）糊了，拍近或换粗档」——**都不是让你去重印**。
- **一页都读不出**：先确认扫描没被"自动裁剪"、没被转成灰度（只有 `monoSafe` 的 profile 才保证单色可恢复 ✓）。
- **缺页**：接收页会点名缺哪几页；补拍那几页即可。冗余比例由发送时的 `--parity` 决定。
- **发送页点了下载、文件却没出现**：产物大时（阈值 32 MB）页面会**先提示**"这一页是把它变成约 X MB 的 data: URL 文本再交给浏览器下载的……页面无法知道下载有没有成功"⇒ 这不是解码失败，是浏览器下载大 data: URL 的固有风险。出路：**电脑上有 Node 就用 CLI 直接写盘、不经浏览器** —— `node cli/pskit.mjs send 你的文件 --profile P-M1-300 --format png,pdf --out 目录`（页图与 `pack.pdf` 都落在目录里，没有浏览器参与）；或者**把文件切小、分几次传**。第 70 轮起这条提示由 `downloadPlan()` 决定（D63）。
- **发送页说「too many pages: N data pages leave no room for parity」/「装不下，而且是协议装不下」**：这不是浏览器的问题、也不是 bug，是**协议的硬上限**：页头的 `totalPages` 只有**一个字节**（`core/frame.js:19`）⇒ **一次传输最多 255 页**，而其中一部分要留给页间校验页，挤到没位置时 `core/protocol.js:320` 就拒绝。实测容量：`P-M1-300` 每页净 **7514 B**（`geom.ecc.dataBytes`），默认 20% 校验页 ⇒ 一次最多约 **1.52 MB**（1 MiB → 168 页装得下；2 MiB → 48 ms 被拒）。三条路：① **把校验页 % 调低**（0% 时约 1.81 MB，代价是丢页时恢复能力下降）；② **换每页装得更多的档**（600 dpi 或四色档，代价是对打印/扫描精度要求更高）；③ **把文件切成几份分别传**（第 72 轮起有现成命令，不必自己拿剪刀：`node cli/pskit.mjs split 文件 --out 目录` ⇒ 每份各自 send/打印/扫描/receive 回同一目录同名 ⇒ `node cli/pskit.mjs join 目录 --out 输出`，逐份校验摘要再校验整文件摘要，缺一片就 exit 1 且不写盘；步骤见上文「一次能传多大」）。**CLI 不能绕过这条限制** —— 它走的是同一个 `encodeTransfer`，同样撞 255 页（CLI 自己的拒绝语是 `needs N pages > 255 (inter-page RS limit): shrink payload or use a denser profile`）。另外：**发送页在读入文件之前只会警告、不会拒绝**，因为页数取决于 deflate 能压掉多少，而压缩比没有上界（本项目自己的 deflate 把 4 MiB 全零压成 **6 页**）⇒ 任何"按文件字节数提前拒绝"的阈值都会**误拒**本来装得下的文件（例如一个 20 MB 但压得动的日志）。第 71 轮起：`transferBudget()` 算账（与编码器逐项对齐，由 `tools/smoke-sender.mjs` 用编码器自己的输出钉住）、`pageLimitHint()` 出拒绝语、`earlySizePlan()` 只负责提前告知（D65）。
- **接收端说「需要口令」/ CLI 打 `receive: NEEDS PASSPHRASE`**：这批是**加密传输**（发送时填了口令）。CLI：同一条命令加 `--passphrase <口令>` 重跑 —— **页图还在磁盘上，不必重印、不必重扫**；桌面接收页：在第 2 节「口令」里填好，再按一次「3 · 开始还原」（已选的文件还在，不用重选）；手机连拍：**先填口令再按「开始连拍」**（连拍不留已解出的页，事后补口令要重拍）。口令**错**了会被摘要门拒（`digest-mismatch`），**不会**交出一个错文件。**第 73 轮之前这三处都只会说"缺页 / 仍缺料 / 未知原因"**，而进度行明明写着 N/N ⇒ 已修（**D66**）：core 现在也把这个原因写进 `error`（`need-passphrase`），三个接收端各给一句能照着做的话。
- **报 `digest mismatch`**：这是**设计行为**——宁可失败也绝不交出"看起来成功但是错"的数据（误接受为 0 是本项目的硬约束）。
- **想自己验内核**：`node cli/pskit.mjs verify --gate all`（G0 单测 + G1/G3/G5/G7/G8 进程内），或接收页 `?selftest=1`。单测条数每轮都在长 ⇒ **别背数字**：**第 59 轮实测 `tests 297 · pass 297 · fail 0 · duration_ms 136148`（≈136 s）、`exit 0`**（第 52 轮是 296/296，第 53 轮加了"纸面斜拍"1 例 ⇒ 297；第 53 轮当轮没抄下汇总数字、那时就没写 ✗ 现在补上了 ✓）⇒ 以 `node --test --test-isolation=none "tests/unit/**/*.test.mjs"` 自己打印的汇总为准，**只看 exit code 判定** ✓
